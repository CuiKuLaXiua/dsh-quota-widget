写法变成声明式

由全局委托统一接管
document.addEventListener("mouseover", e => { const el = e.target.closest("[data-tip-head]"); if (el) oqTip.show(el, parseTip(el)); });
强项：接入任一新位置只需加 2~3 个 data 属性，不用碰 JS 逻辑。全局委托还能顺手解决"滚动/切 tab 时 tooltip 悬空"这类通病。
代价：属性是字符串，复杂内容（色点、多列）表达不了，只能退化成纯文本行 —— 反而丢掉了热力图那套的富样式。要支持富内容就得回到 B 的 JS 调用式。
另：React 里 data-* 走原生 DOM 事件，与现有 jsx 桩测试的兼容性需要额外验证。

我的建议：B。理由是热力图那套的价值不在"样式"，而在富内容结构（head / main / rows / div / lv 五层）。 A 会把同样的定位+动画逻辑复制 5 遍，以后改一次要改 6 处；C 的声明式很省心，但字符串属性撑不起色点与分栏，最终会退化成"漂亮一点的原生 title"。
另外两处值得一起做：Live 三态徽标（色弱用户的唯一通道，现在只有一句纯文本）与圆环（目前悬停完全无反馈，可给出命中率的算式：缓存读 ÷(新输入+缓存读)）。
