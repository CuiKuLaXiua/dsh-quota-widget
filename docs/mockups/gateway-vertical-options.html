网关用量：垂直关联的四种做法

改动要点：① 网关值从 97.8% 改成实际 token 数（100.4M），百分比退到次要位置；② 用垂直方向的结构关系（共边框 / 轨道 / 分段条 / 连接角）表达「网关属于总量」，而不是靠水平并置。

数据基准（与你的截图同源）：总量 102.7M，其中网关 100.4M（97.8%），本机 2.3M。
为什么垂直就能解决误读：误读的本质是「水平相邻 = 同一主语」。把两个数改成上下从属，读者的解析顺序会天然变成「总量 → 它下面的子项」，模型名在另一个水平层级，不再参与竞争。

强项：胶囊（你指定的样式）+ `其中` 二字把关系**写死在文字上**，最不可能误读；两个胶囊宽度不同（下窄上宽）也能暗示从属。
代价：+28px，四版里最高；三个元素（胶囊+连接角+胶囊）在 260px 里略显啰嗦；`其中` 与上面的 `总量` 语义重叠。
适合：你最不能容忍误读，宁可多占地方也要把话说死。

我的判断：C 是这四版里唯一"图本身就说明比例"的（那根竖条），而且顺手把本机值也给了出来；B 是视觉最克制、最不会抢戏的；A 是结构最规整、最适合以后还要加第三个子项的。

如果要更省高度，还有一个「A 的压缩变体」：把总量留在第一行（`102.7M Token`），只在模型名那行下面加**一行** 其中网关 100.4M —— 只增 11px，但归属靠"其中"二字，不如 A 的共边框硬。这个变体我可以在你选定主方向后一并给出。
