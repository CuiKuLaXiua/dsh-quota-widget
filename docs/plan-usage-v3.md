## 2. 现有功能的增强（按卡片）

### 2.1 总览
- 环比改日均 + 覆盖度守卫（见 A1）。
- 增加**换算指标**：日均 token、每轮 token、每步 token（判断"对话效率"比看总量有用）。
- 96% 命中率说明"几乎全在吃缓存"，可加一句结论型文案：「新输入仅占 3.6%，节省显著」。
- 可选：**缓存节省估算**（需价目表，见 §4-D）。

### 2.2 图表
- 热力图：月份切换 + **点击某天 → 下钻当日分时**（现在只能看"今天"）。
- 折线模式增加**按日命中率**曲线（`daily[].cache_read` / `prompt` 已有，零新增采集）。
- 增加**本期 vs 上期**双线（需要 host 返回 `prevDaily`，小改）。
- 柱状图补 y 轴刻度数值（现在只有"峰值"一个标注）。

### 2.3 模型排行
- **标注/拆分渠道**：实测 `deepseek-v4.1-flash` 跨 2 个渠道，现在被合并成一行，费用归属会错。
  建议行内显示 `u2-flash · unisound`，或加「按渠道拆分」开关。
- 支持「展开全部 N 个」（现在固定 top5 + 其他）。
- 每行加 7 日 sparkline（`daily[].models` 已有）。

### 2.4 实时
- **可靠性目前只在本次启动有效**（retry/compaction 事件不落库），重启即归零 → 加"本次启动"角标
  已做，但更好的是把这两类计数按天落库（见 §3-C2）。
- 速率在空闲时显示 `0.0` 容易误判成故障 → 已改为「（空闲）—」，再补「最近一次生成速率」。

### 2.5 卡片组织（截图里最影响体感的一点）
- 目前 9 张卡片纵向堆叠（总览/图表/模型/工具/项目/渠道/实时/最近调用），设置面板里要滚很久。
- 建议：**排行类四合一**——「模型 | 工具 | 项目 | 渠道」分段切换，一屏只看一个；
  折叠状态记忆在 localStorage。这样总高度少 3 张卡。

## 3. 功能拓展（按"数据是否已在手"分档）

### C1 数据已在手（只改客户端/小改 host）
1. **会话排行 Top N**：62 会话、Top8 占 70% → 价值最高的一张新卡；会话标题可读（`session/title` 已有）。
   需要 host 新增 `daily_session` 派生表（或直接在 `computeUsage` 里按 session 聚合 events）。
2. **效率指标卡**：tokens/step、tools/step、平均步耗时、每轮请求数（全部握手算）。
3. **命中率趋势**（按日折线，见 2.2）。
4. **本期 vs 上期对比**（需 `prevDaily`）。
5. **时间热力（小时×星期）**：实测 9–11 点与 17 点是峰值、周三是峰值 → 很直观；
   但需要把小时桶按 `(dow, hour)` 持久化（现在 `realtimeHourly` 只保 2 天）。

### C2 需小改采集
6. **工具失败率落库**：`tool/result.isError` 只在内存计数 → `daily_tool.errors`，可出"失败率"列。
7. **重试/压缩按天落库**：`llm/retry`、`compaction/end`、`command/done` 的 "Compacted N items (~X tokens)"
   → 「压缩次数 / 被压缩 token 量 / 重试 Top 原因」，不再随重启归零。
8. **会话标题落库**：`session/title` → 最近调用与会话排行显示标题而不是 12 位 id。
9. **`prevDaily`**：环比图表需要。

### C3 需新能力（决策类，建议后置）
10. **预算与告警**：日/月 token 预算、阈值提醒。
11. **配额联动预测**：`/api/opencode/quota` 已有 used/limit/percent + 当前用量速率 → "按当前速率 X 小时耗尽"。
12. **成本估算**：需要可编辑价目表（input/output/cache_read 三档），否则只做 token 相对量。

### 6.2 数据链路变化（schema v5）

- `events` 增补 `err`（失败标记）/ `num`（整数值，目前只放"被压缩 token 数"）；`daily_tool` 增补 `errors`。
- 新增派生表：`daily_session`、`daily_hour`、`daily_reliability`、`daily_retry`。
- 落库事件类型扩容：`llm/retry`（`raw` 存 failure code）、`compaction/end`、`command/done`、`session/title`。
- 一次性回填 `backfillExtra()`：v4 及以前这些事件从未落库，重读会话文件只补这四类（绕水位线），
  然后重建可靠性表并置 `meta.extra_backfill=1`。
